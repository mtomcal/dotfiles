## Proposed changes

### Add

- Add the exact WF-008 definition of **Wayfinder effort**: “bounded uncertainty-resolution undertaking represented by a map and tickets.”
- Add one `Workflow` section around the five existing ordered lifecycle steps, with open-versus-chart routing first.
- Add one `Reference` section containing a mandatory pointer to `FORMATS.md` whenever creating or changing a Wayfinder map or ticket, because that file owns exact map/ticket schemas, ticket types/statuses, blocker and transition semantics, and durable-state exclusions.
- Add one compact composition-ownership rule beside ticket dispatch: composing a type owner imports its process only; Wayfinder retains the destination, map/ticket state, user gates, and return criteria.

### Change or move

- Preserve frontmatter byte-for-byte, including the existing description triggers, short description, union schema, and tool grants.
- Rename `Core model` to `Language Definitions` and use the exact WF-008 wording for Destination, Wayfinder effort, Decision ticket, Fog of war, Frontier, and Out of scope. Keep repository glossary wording authoritative where terms overlap.
- Nest the existing five numbered lifecycle headings under the single Workflow without changing their sequence: open/chart; choose frontier; resolve uncertainty; record/clear fog; complete/route onward. Nest Herdr delegation under resolution.
- In open/chart, preserve existing-map loading, frontier-only ticket loading, `grill-me` destination/scope selection, breadth-first sharp-question/fog separation, direct `create-plan` route when one planning context is enough, approval before `.wayfinder/` creation, mandatory format loading, map/ticket creation before a second blocker-edge pass, parent-only state writing, and the stable-destination/noncontradictory-frontier completion criterion.
- In frontier selection, preserve derivation from open tickets whose blockers are all resolved, the prohibition on treating `out-of-scope` as a resolved blocker without revising the dependent ticket or edge, named-valid-ticket/first-numeric selection, parent transition to `in-progress`, exactly one non-research decision ticket for the session, and safely parallel independent research without bypassing blockers.
- In ticket resolution, preserve routing by `research`, `prototype`, `grilling`, or prerequisite-only `task`; preserve evidence sufficient for one explicit answer and no opportunistic production behavior. Keep prototype conclusions while removing or isolating throwaway code and keep the human responsible for their side of grilling decisions.
- In delegation, preserve `HERDR_ENV=1` loading of the Herdr owner for useful independent read-only investigations, delegate return through pane output, parent-only `.wayfinder/` edits, live ID refresh with no durable IDs, shared checkout only for read-only work, isolated worktree/clone for any editor, and the complete in-process direct fallback with source notes before synthesis.
- Preserve the implementation stop: capture the decision and defer production execution to `create-plan` when resolution starts becoming implementation.
- In resolution recording, preserve parent-written answer and all six update paths: final status; linked low-resolution map gist only for resolved route decisions; newly sharp tickets and blocker edges; fog graduation/removal; invalidated ticket/edge revision; and reasoned Out of scope entries with links where applicable.
- Preserve one durable home for detailed decisions, descriptive human-facing ticket titles with linked IDs, mutually exclusive map sections, and frontier recomputation from ticket files alone.
- In completion, preserve the full test: destination clear, no open/in-progress tickets, and no in-scope fog. Preserve the empty-frontier inconsistency warning, `update-specs` route for durable behavioral/design/terminology decisions, conditional `ubiquitous-language` route when terms changed, `create-plan` route for implementation, and retention of `.wayfinder/` unless repository policy says otherwise.

### Remove

- Remove only the obsolete heading name `Core model` and the five lifecycle steps' level-two placement after their content moves under canonical sections.
- Remove no trigger, definition meaning, open/create/approval/state path, map/ticket format rule, ticket type, status, blocker/frontier/out-of-scope semantic, parent ownership rule, one-ticket/parallel-research constraint, composition route, delegation/fallback/isolation rule, implementation stop, resolution/map/fog/edge update, one-home rule, completion condition, or onward route.
- Add no `Activities`, support file, script, tracker/database integration, issue-tracker identity, implementation behavior, universal plan semantics, or additional terminology.
