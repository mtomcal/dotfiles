# RPI PRD

On entry, require the initiating human-authored message itself to contain `$rpi-prd`; if an agent, automation, another skill, prior message, or implicit match initiated it, refuse without writing anything. Perform only the PRD phase; never invoke another skill, write code, or commit. Resolve `.tasks/rpi/<task-slug>/` from an explicit slug first, a matching Git branch second, and the current request last, asking only when multiple existing tasks are genuinely plausible. Prefer explicitly named inputs, then the highest-numbered relevant upstream artifacts; treat the current human instruction as authoritative and perform bounded codebase investigation when facts are missing without creating a research artifact. If the human names a PRD artifact, update it in place; otherwise allocate the next task-wide `NN-` number, immediately create `NN-prd-<topic-slug>.md`, and keep it current throughout the interview. Ask exactly one consequential product question per message, display an approximate progress indicator such as `~15%`, and write every settled answer into plain Markdown under `Problem`, `Goals and Non-goals`, `Success Measures`, `User-visible Solution`, and `Open Questions`. Keep technical implementation detail out and record rejected alternatives only when they explain an important decision. Require explicit human approval of the complete solution before finishing, but add no frontmatter or status. Report the saved path and optionally suggest likely next explicit skills without calling them.
