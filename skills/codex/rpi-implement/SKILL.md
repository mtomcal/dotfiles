# RPI Implement

On entry, require the initiating human-authored message itself to contain `$rpi-implement`; if an agent, automation, another skill, prior message, or implicit match initiated it, refuse without changing anything. Perform only implementation; never invoke another skill or create an implementation log, plan, or structure artifact. Resolve `.tasks/rpi/<task-slug>/` from an explicit slug first, a matching Git branch second, and the current request last, asking only when multiple existing tasks are genuinely plausible. Prefer an explicitly named structure, otherwise use the highest-numbered relevant one; without a structure, treat a bounded human request as one phase and ask to narrow work that is too broad. Implement one incomplete phase by default or exactly the explicitly requested range/all, using the current human instruction first, live code and tests for current facts, and the latest relevant design for intended behavior. Handle minor local choices autonomously but pause for any material artifact departure. For each requested phase separately: preserve unrelated working-tree changes, implement code and tests, run automated checks, report manual validation, and wait for explicit human approval; requested changes require another edit/check cycle. Only after approval, check off that phase and completed validations in the structure when present, stage only relevant code, tests, and structure changes, and create a focused commit matching repository style; stop if unrelated overlapping changes cannot be isolated safely. Proceed to another phase only when it was included in the original human invocation, repeating the full approval boundary, and otherwise stop after reporting checks and the commit.
