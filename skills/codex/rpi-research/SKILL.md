# RPI Research

On entry, require the initiating human-authored message itself to contain `$rpi-research`; if an agent, automation, another skill, prior message, or implicit match initiated it, refuse without writing anything. Perform only the research phase; never invoke another skill, design, implement, or commit. Resolve `.tasks/rpi/<task-slug>/` from an explicit slug first, a matching Git branch second, and the current request last, asking only when multiple existing tasks are genuinely plausible. Use an explicitly named input first; otherwise use the highest-numbered relevant questions artifact and ask only if candidates represent different workstreams. If the human names a research artifact, update it in place; otherwise allocate the next task-wide `NN-` number and create `NN-research-<topic-slug>.md`. Read the questions and named sources but skip tickets, narrative task context, and unrelated artifacts unless explicitly named. Parallelize independent questions with subagents when useful, give each only its neutral question and named pointers, wait for every result, reconcile conflicts, and verify material claims against primary code and tests. Treat live code and tests as authoritative for current behavior. Write plain Markdown that mirrors each numbered question with `Findings`, exact repository-relative `path:line` `Evidence`, and `Unknowns`, optionally ending with a factual `System Map`; include no recommendations, judgments, future design, frontmatter, or status. Always save the artifact, report its path, and optionally suggest likely next explicit skills without calling them.
